# 판 시뮬레이션

사람 대신 봇이 조준해 판을 돌린다. Unity 없이 게임 Core를 그대로 쓴다.

- 봇·판 실행·전체 루프: `Assets/Scripts/Simulation`(어셈블리 `BlackHole.Simulation`, 에디터·개발 빌드에서만 컴파일, Core만 참조).
- 실행기: `Tools/Simulation`(.NET 8 콘솔). 레포의 실제 에셋(GameContentSetup과 그 아래 에셋, 노드 CSV·배치)을 읽어 게임과 같은 정의를 만든다.

## 실행

레포 맨 위에서(.NET 8 SDK):

```
dotnet run -c Release --project Tools/Simulation -- campaign
dotnet run -c Release --project Tools/Simulation -- campaign --runs 10
dotnet run -c Release --project Tools/Simulation -- battle --bot both --scenario Assets/Playtest/Scenarios/qa-nodes-8.json
```

| 명령 | 하는 일 | 주요 옵션 |
| --- | --- | --- |
| `campaign` | 처음부터 클리어까지 전체 루프 | `--bot greedy\|circle`, `--seed N`, `--runs N`(시드를 1씩 올리며 N번), `--max-battles`(5000), `--stall`(300), `--max-seconds`(판 하나 상한 3600), `--fps`(60), `--out 폴더` |
| `battle` | 고정한 세팅으로 판 몇 개 | `--bot greedy\|circle\|both`, `--nodes none\|all`, `--scenario 세팅 JSON`, `--stage N`, `--seeds N`(3), `--max-seconds`(600) |

결과는 기본으로 `PlaytestData/sim/<시각>-<봇>-s<시드>/`에 쓴다(`PlaytestData/`는 git 무시). 10번 돌리는 데 약 40초 걸린다(클라우드 기준).

## 전체 루프 규칙(`CampaignRunner`)

1. 빈 진행 상태(Gold 0, 성장도 0, 노드 없음)에서 시작한다.
2. 판: 산 노드의 수치로 판을 만들고 봇이 끝까지 조준한다. 실제 게임(`BattleSystem`)과 같은 순서로 끝내고 결산한다. 이정표 판은 결산이 잔액을 목표 Gold까지 채운다(그 판에서 번 Gold는 버린다 — 게임 규칙).
3. 구매(`CheapestFirstBuyer`): 지금 살 수 있는 노드 중 다음 Rank가 가장 싼 것부터 살 수 없을 때까지 산다. 값이 같으면 노드 ID 순서(테스트 세팅의 자동 구매와 같다).
4. 마지막 이정표에 닿으면(클리어) 멈춘다. 판 상한, 또는 `--stall`판 연속으로 아무것도 못 사고 이정표에도 못 닿으면(막힘) 멈춘다.
- 판마다의 시드는 실행 시드와 판 번호로 정한다. 같은 콘텐츠·시드면 결과가 같다.
- 판 시간만 센다. 업그레이드 화면, 판 시작 연출, 결산 화면에서 보내는 시간은 없다.
- 판이 제한 시간·이정표로 끝나지 않으면(시간 추가가 흐르는 시간보다 빠름) `--max-seconds`에서 끊고 `capped`로 남긴다.

## 조준 봇

봇은 매 프레임 조준점(마우스가 가리키는 판 좌표)을 정한다. 실제 게임의 `AimInput`과 같은 자리다: 봇의 `Aim` → `GameSession.SetAimPoint` → `GameSession.Advance`. 봇은 판을 읽기만 한다.

| 봇 | 이름 | 하는 일 |
| --- | --- | --- |
| `GreedyAimBot` | greedy | 사람처럼 조준한다(아래). 기본 봇. |
| `CircleAimBot` | circle | 판을 보지 않고 블랙홀 둘레(반지름 6 × 전장 배율)를 초당 0.7라디안으로 돈다. 비교용 하한선. |

### 탐욕 봇이 고르는 법

- 후보 자리는 모든 적의 위치다. 그 자리에 Breaker 원을 두면 닿는 적들의 값어치를 더한다.
- 적 하나의 값어치 = Gold × min(1, 한 번 치는 피해 ÷ 남은 HP). 한 번에 죽으면 Gold 전부, 아니면 깎는 비율만큼이다. 피해에는 종류 보너스(행성·별·은하)와 치명타 기대값(혜성 버프면 확정 치명타)을 넣는다.
- 점수 = 값어치 ÷ (1 + 옮겨 가는 시간 ÷ 공격 주기). 멀면 가는 동안 못 치므로 깎는다.
- 점수 상위 몇 자리는 닿는 적들의 가운데로 한 번 옮겨 다시 매긴다(무리 한가운데를 노린다).
- 지금 목표보다 30% 이상 좋을 때만 바꾼다. 혜성은 가장 좋은 일반 목표 한 번의 1.5배로 보고, 가까우면 먼저 줍는다.
- 판의 모든 적이 보인다(카메라가 전장 전체를 보여 준다). 남은 HP·Gold도 안다고 본다(색 등급·크기로 사람이 어림하는 값).

### 사람처럼 보이게 하는 것

| 수치(`AimBotProfile`) | 기본 | 뜻 |
| --- | --- | --- |
| `DecisionSeconds` ± `DecisionJitter` | 0.3 ± 0.1초 | 평소 목표를 다시 고르는 간격 |
| `ReactionSeconds` | 0.2초 | 고른 목표로 손이 움직이기 시작할 때까지 |
| `PulseRetargetSeconds`, `PulseMoveSeconds` | 0.2초, 0.05초 | 공격이 터지면 바로 다음 무리로(리듬을 아는 손). 단 0.2초보다 자주 꺾지 않는다 |
| `MaxSpeedScreens` | 1.6 | 커서 최대 속도(화면 높이/초). 화면 위에서 아래까지 약 0.6초 |
| `ApproachGain` | 10 /초 | 목표 근처에서 부드럽게 멈춘다 |
| `AimErrorScreens` | 0.005 | 조준 오차(화면 높이의 0.5%, 표준편차). 목표를 고를 때마다 새로 뽑는다 |
| `SwitchMargin` | 0.3 | 작은 이득으로는 목표를 바꾸지 않는다 |
| `PickupWorth` | 1.5 | 혜성의 값어치 배수 |

- 목표는 "기준 적 + 어긋남"이라, 적이 공전해도 그 무리를 따라간다.
- 거리·속도는 화면 높이 비율이다. 전장 배율이 커지면 화면도 커져서 사람에게는 같은 손놀림이다.
- 같은 시드면 같은 판에서 같게 움직인다.

### 측정 (2026-10-11, 판 3개 × 60초, 초당 60번 진행)

| 세팅 | 원 궤도 봇 Gold | 탐욕 봇 Gold | 프레임 첫 공격이 빈 비율(원 → 탐욕) |
| --- | ---: | ---: | --- |
| 첫 판(노드 없음, 12초) | 0 | 4 | 97% → 8% |
| 1~8단계 | 5.8e15 | 14.1e15 | 10% → 17% |
| 모두 산 판 | 65.8e15 | 121.1e15 | 5% → 11% |

탐욕 봇은 값비싼 무리를 찾아가므로 같은 판에서 Gold가 2~2.5배다. 공격이 빈 비율은 무리를 옮겨 다니는 동안 생긴다. 숫자는 비교용이다: 실제 사람의 기록과 맞춰 수치를 고친다.
